# 🛡️ ProSourcing 系统灾难恢复与数据还原手册 (v1.0)

**文档说明**：本手册用于在 ProSourcing 系统出现数据崩溃、乱码或迁移新机器时，利用备份文件快速恢复系统到稳定状态。

---

## 📅 备份准备 (建议每周执行)
在一切正常时，请确保你拥有以下备份文件：
1. `backup_full_data.sql` (数据库全量备份)
2. `output/` 文件夹 (历史任务原始数据)
3. `scripts/` 文件夹 (所有修复和维护脚本)
4. `.env` 文件 (系统环境变量与密钥)

---

## 🛠️ 第一阶段：环境彻底清理
在还原前，必须确保旧的错误数据被清除。

```powershell
# 1. 停止所有服务
docker-compose down

# 2. 清理残留数据卷 (这一步会清空所有旧的数据库物理文件)
docker volume rm prosourcing_db_data
```

---

## 💾 第二阶段：数据库还原
将 SQL 备份文件重新灌入系统。

```powershell
# 1. 重新拉起基础容器服务
docker-compose up -d

# 2. 等待数据库初始化完成 (约 10 秒)
Start-Sleep -Seconds 10

# 3. 执行还原指令 (假设备份文件在当前目录下)
cat backup_full_data.sql | docker exec -i prosourcing_db psql -U postgres -d prosourcing
```

---

## 📂 第三阶段：物理文件恢复
1. 将备份的 `output/` 文件夹覆盖到项目根目录。
2. 将备份的 `scripts/` 文件夹覆盖到项目根目录。
3. 确保 `.env` 文件内容正确。

---

## 🔧 第四阶段：ID 与日期修复 (治本步骤)
如果还原后分类树日期未显示，请执行此脚本重新对齐 ID：

```powershell
# 1. 拷贝修复脚本到容器
docker cp ./scripts/recover_category_ids_from_history.py prosourcing_backend:/app/scripts/

# 2. 执行 ID 与日期一键修复
docker exec -it prosourcing_backend python /app/scripts/recover_category_ids_from_history.py
```

## 🆘 常见问题应急预案 (FAQ)

### 1. 还原后网页显示 0 或不刷新？
- **解决**：在浏览器按 `Ctrl + F5` 强制刷新缓存。若无效，执行 `docker-compose restart` 重启整个后端。

### 2. 提示 "database already exists" 还原中断？
- **解决**：先手动删除旧数据库：
  `docker exec prosourcing_db psql -U postgres -c "DROP DATABASE prosourcing;"`
  `docker exec prosourcing_db psql -U postgres -c "CREATE DATABASE prosourcing;"`

### 3. ID 匹配不上的老毛病又犯了？
- **解决**：直接运行 `recover_category_ids_from_history.py`。该脚本采用“名称对齐”逻辑，专门解决新老 ID 不一致的问题。
