## 2. 前期：本地电脑部署方案 (Local Setup)

这是最推荐的“冷启动”方案，适合脚本打磨周期。

### 2.1 硬件要求
- **内存**：建议 **16 GB** (Chrome 多开+后端+前端)。
- **操作系统**：Windows 10/11。

### 2.2 核心操作步骤
1. **网络准备**：开启全局代理模式，确保能流畅访问 `Kaspi.kz` 和 `Algatop.kz`。
2. **环境搭建**：
   ```bash
   pip install -r requirements.txt
   playwright install chromium
   ```
3. **RPA 启动**：运行 `launch_rpa_chrome.py`，在打开的 Chrome 中手动完成登录。
4. **服务运行**：运行 `start_backend.py` 和 `npm run dev`。
5. **外网映射 (可选)**：如需异地展示，使用 `cpolar` 或 `ngrok` 进行内网穿透。

## 3. 进阶：腾讯云服务器方案 (Cloud VPS)

适合需要 24 小时自动采集及多人协作预览的阶段。

### 3.1 推荐配置
- **机型**：轻量应用服务器 (Lighthouse)。
- **规格**：**4 核 8G 内存**（内存是 Chrome 运行的红线）。
- **地域**：**中国香港**（必选！跨境网络质量直连中亚站点）。
- **宽带**：5 Mbps 以上。

### 3.2 部署策略
- **系统**：首选 **Windows Server 2019/2022**，方便直接远程进去手动维护账号 Session。
- **持久化**：备份 Chrome 的 `User Data` 目录，确保服务器重启后无需重新扫码登录。

---

## 4. 其它：Runway/Railway 兼容性分析 (PaaS)

如果你希望使用现代化的 PaaS 平台：
- **可行性**：仅支持 **React 前端** 和 **FastAPI 后端** 的部署。
- **不可行性**：**RPA 采集引擎无法在容器内运行**。因为容器内无法显示图形界面让你手动输入账号密码，且容器的动态 IP 极易触发 Algatop 的风控封禁。
- **建议**：采用“动静分离”，业务系统放云端，采集引擎跑在你的本地或 VPS。

---

## 5. 项目安全性与账号维护
- **IP 保护**：无论在哪部署，采集频率切忌过高，建议模拟真人翻页间隔（3-10秒）。
- **Session 守护**：由于 Algatop/Kaspi 对异地登录较敏感，尽量固定一台设备和固定 IP 进行采集。
